# The FMU pack (STD-01): what the engine needs to run FMU parts. Optional:
# without it every other model runs and Data Checks say FMU support is missing.
#
# FMPy itself declares more than it needs here (cmake, a 42 MB wheel, plus
# jinja2 and nbformat, used only to compile source FMUs and write notebooks),
# so install it without its declared dependencies, after these:
#
#   pip install -r requirements-fmu.txt
#   pip install --no-deps "fmpy==0.3.32"
#
# Licences: FMPy BSD-2-Clause; attrs and lark MIT; NumPy and lxml BSD-3-Clause
# for their own code, but their binary wheels also carry other code: GNU
# libiconv, linked into lxml's modules (LGPL 2.1, every platform), and in
# NumPy the GCC runtime (libgfortran, GPL-3.0-or-later with the GCC Runtime
# Library Exception) plus, in its Linux wheels only, libquadmath
# (LGPL-2.1-or-later). The desktop build takes the pack in
# (LIGHTSIM_FREEZE_FMU_PACK=1): the LGPL parts ship unmodified in their
# packages' own files, listed in the notices with their source (the owner,
# 20 October 2026; see lightsim-backend.spec). lxml from 6.1.3 (6.1.1 names
# no libiconv in its licence file, though its wheels hold it), which names it,
# as the notices check reads (scripts/licenses/clarifications.json).
numpy>=2.1.3
lxml>=6.1.3
attrs>=24.2.0
lark>=1.2.2  # FMPy's variable-name check (fmpy.validation)
